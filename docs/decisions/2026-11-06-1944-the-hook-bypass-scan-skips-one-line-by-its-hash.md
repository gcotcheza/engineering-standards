# The hook-bypass scan skips one line by its hash

Card 946 (S1), an extension of `the-hook-bypass-scan-has-one-copy` (card 746), which it does not supersede: the skips stay arguments, and a bare path keeps its whole-file meaning. An argument holding a colon is a line skip, `<path>:<sha256 of the statement>`, split at its first colon; the hash is 64 lowercase hex, anything else exits 2, so a path holding a colon cannot be named, and a listed file whose path starts with a line skip's path and a colon also exits 2. An empty path, or one holding a newline, exits 2 (advisor and devbox16 rulings, 2026-11-06; a skip file was ruled out).

**Why a hash, not the text.** The first form carried the line's text, so the gate script passing it held the flagged text and was itself a finding. A hash names the line without repeating it.

The hash is of the statement (all its physical lines) exactly as the file holds it: a statement continued past trailing backslashes is hashed whole, its lines joined by one newline, with no trimming, no final newline and every CR kept, so a CRLF ending, a trailing blank or a line inserted into the statement changes it (`printf '%s' "$(sed -n '<first>,<last>p' <file>)" | sha256sum`). Hashing only the first line let a route be inserted as a middle continuation line under a standing skip (review round 1). A line skip permits one finding statement in that file with that hash; a second is a finding, and an app that means two gives the argument twice. Every applied skip is printed on stdout on every run, in argument order, `hook-bypass-scan: skipped <path>:<n> sha256 <hash> (<k> finding statement(s) hash to it): <statement>`, every line of it, so a reviewer reads the text the hash stands for. A line skip given more times than finding statements hash to it is stale: exit 1, naming it. A `sha256sum` that gives no hash exits 2. Any other finding in a file with line skips, including a new route added beside a skipped one, stays a finding.

This repository's gate now skips `scripts/lib/deploy/test.sh` by its one finding line (the `git-as` shim's `env -u HOME`, which 746 skipped whole) instead of the whole file, so a new route added to that file is a finding; the other six skips stay whole paths.
