# The hook-bypass scan skips one line by its text

Card 946 (S1), an extension of `the-hook-bypass-scan-has-one-copy` (card 746), which it does not supersede: the skips stay arguments, and a bare path keeps its whole-file meaning. An argument holding a colon is now a line skip, `<path>:<line text>`, split at its first colon, so the text may hold colons but the path may not; a listed file whose path starts with a line skip's path and a colon is refused with exit 2, since no argument can name it. An empty path or text, or a text holding a newline, is refused with exit 2 (advisor rulings, 2026-11-06).

A line skip permits exactly one finding line in that file whose text, as written, equals the argument: no trimming, so leading or trailing blanks and a CRLF ending do not match. A second finding line with the same text is a finding; an app that means two such lines gives the argument twice, so every permitted line is one argument a reviewer reads. A line that continues past a trailing backslash is matched on its first line, where the finding is reported. Every applied skip is printed on stdout on every run, `hook-bypass-scan: skipped <path>:<n> (<k> finding line(s) have this text)`, where k counts every finding line in the file with that text. A line skip that permits nothing, because its file, its line or the finding on it is gone, is stale: exit 1, naming it, so the list cannot rot. Any other finding in a file with line skips, including a new route added beside a skipped one, stays a finding.

**The limit found while building it.** The argument holds the flagged text, so the file that passes it (an app's gate script) holds that text too, and the scan judges that file: a line skip written literally into a gate is itself a finding. This repository's gate therefore keeps its seven whole-path skips, including `scripts/lib/deploy/test.sh`, whose one finding line would otherwise be the first candidate. Where an app keeps its line skips, so that they reach the scan without being judged as code, is open for the advisor; `docs/` is never scanned, so a list under `docs/` read into arguments by the gate is one route that needs no scanner change.
