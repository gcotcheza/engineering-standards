# The gate's root-owned check lives in the deploy lib

Seven apps (Fineprint, GhieCode, Ghie Writes, Health Tracker, Memento, Reflection, Scribly) each carry their own `scripts/root-owned-check.sh`, the last gate step that refuses a tree holding any path root owns. All seven differ. C1 says the third copy is where the code is extracted, so the check is now `root_owned_check <dir>` in `scripts/lib/deploy/ownership.sh`, beside the deploy's own `root_owned_count`. Apps do not vendor it: their gates already source the lib from the one copy on the box through `DEPLOY_LIB` (decision: t9-follows-the-deploy-lib), so each app's gate calls `bash "${DEPLOY_LIB}/ownership.sh" <tree>` (the command entry, as `compose.sh` has one) or sources the file and calls the function, then deletes its own copy in its own pull request.

The function is a subshell body, GhieCode's shape, so its `exit`, a refusal included, never ends or changes the gate that sourced it. It prints one line on stdout and returns 0 when the tree is clean; otherwise it names the first 50 paths on stderr and how many more, with the count exact, then the remedy last, where a `tail` finds it, and returns 1. The remedy reads the owner off the tree's top, as Scribly's does, because one hardcoded app name is wrong in every other app's worktree: write as `runuser -u <owner>`, fix the writer and never the file, and only once the writer is fixed hand the tree back with `chown -R <owner>:<group> <tree>`. When root owns the top too, the remedy says that name is not the app user.

The predicate is `find -P <dir>/ -xdev -ignore_readdir_race -user 0`, the deploy's and the fleet health check's own, walked once: each path goes to a list in a temporary file and one dot to the count, so a newline in a name miscounts nothing. `DEPLOY_ROOT_UID` moves the uid only when the test seam `OWNERSHIP_TEST_ROOT_UID=1` is set too, because a stray non-root uid in a gate's environment would otherwise clear every tree; `root_owned_count` is unchanged. The refusals are `root_owned_count`'s: a link or a path with a trailing slash over a link, a non-directory, a relative or empty path, and a path that is not its own real path (a linked parent, a `.` or `..` part), compared literally so a glob character in a name cannot match another path. A failing `mktemp` or `find` refuses, and is never read as clean. The remedy's `chown` quotes the tree with `%q`, so a path with a space pastes as one word. The glob refusal is not taken over: it guards `root_owned_count`'s `-path` pattern, and this check has none.

The linked-parent refusal is a tightening. Memento and Scribly resolve a linked start with `pwd -P` and accept it today; Fineprint's and Health Tracker's default tree, a logical `cd .. && pwd`, will now fail loud when reached through a link. A caller passes a physical path (`pwd -P`); the check never resolves one itself, so a linked tree is refused, never walked behind the caller's back.

`-xdev` is in. Memento and Scribly count across mounts today, so for those two the check gets looser: a root-owned path on a filesystem mounted inside the tree is no longer named. That is accepted because a mount inside a worktree is not part of the tree the deploy hands over or sweeps, and the gate should judge exactly what the deploy and the fleet health check judge; a gate that counts more refuses trees the box itself calls clean.

`.claude` is not set aside, unlike `root_owned_count`. The gate must count at least what the deploy counts, and a root-owned file under `.claude/` in a gate worktree is still a root writer to fix, not a deploy-time exception.

Fineprint's copy neither walks `<tree>/` nor resolves the start, so `root-owned-check.sh <a link to a tree>` passes with exit 0 over a root-owned file (proved in a container). No live caller passes a link, so the hole is latent; it closes when Fineprint calls the lib copy, which refuses a linked start outright.

Cases are in `ownership-test.sh` (the `check:` lines); the mutants are in `scripts/deploy-lib-ownership-mutants.txt`, run as root in a throwaway container that may mount a tmpfs. The gate's normal run does not exercise the mount case: it needs CAP_SYS_ADMIN and the opt-in `OWNERSHIP_TEST_MOUNT=1`, and prints as a skip, so the `-xdev` guard is proven by the mutant run (`roc-xdev`) only; the gate container gets no extra capabilities.
