# Every bash run on a script file in scripts/*.sh code names the file after --

Card 1138. The W52 root-exec guard refuses `bash "<expanded path>"` with no `--` in front of the operand, and the operand is a path the shell expands, so a value that begins with `-` would be read by bash as an option rather than as the file. The advisor's ruling (pv agreed) is `--` everywhere, with no list of exceptions. `bash -- FILE` runs FILE exactly as `bash FILE` does.

`scripts/bash-dashdash-scan.sh` holds the line in gate step 4. What it scans is code in `scripts/**/*.sh`: a `bash` word outside quoted strings, comments and here-doc bodies, then its options (short clusters after `-` or `+`, `-o`/`-O`/`+o`/`+O` with their name, long options such as `--norc`, across lines continued with a trailing backslash), then an operand that starts with an expansion. Strings are data until something runs them, and many are fixtures a test feeds to a guard on purpose (the hook-bypass scan's mirrored gate lines, the deploy lib's literal-guard forms), whose exact text is what the test is about. So the `*-mutants.txt` tables (a row's exact-line field must equal the target's line, so a row moves with its target, but its case command is not scanned) and the case strings `guard-mutants-test.sh` runs through `bash -c` are out of scope. `bash -c` takes a string, not a file, and `bash -s` reads its script from stdin and hands the operand over as `$1`, so both are left alone; so is a short cluster holding `c`, `s`, `o` or `O`.

Two commands live in strings that are word-split and then run as root. `GATE_COMPOSE` in `lib/gate/run.sh`, which every app gate runs, now reads `bash -- $LIB/compose.sh`. `DEPLOY_COMPOSE` in the deploy lib's `compose.sh` now reads `bash -- $FLEET_COMPOSE_LIB` too (card 1244, deploy-lib 2026-11-20.1), held by a `compose-test.sh` case on its words and one that runs the lib from a path starting with `-`. The scan cannot see either, because both sit inside double quotes.

Known false positives, loud and harmless: a `bash` word that is an argument, as in `echo bash "$X"`, `grep -q bash "$f"` or `printf '%s\n' bash "$X"`, is flagged; quoting the word (`'bash'`) clears it. Known misses, rare enough to leave: a case arm with no space before the command (`x)bash "$X"`), and a case arm's `)` inside `$( … )`; backticks inside double quotes; `$'…'` strings that hold an escaped quote; `$( … )` inside an unquoted here-doc body; bash reached through a variable (`"$BASH"`); `--rcfile`/`--init-file` with their file; a short cluster ending in `o` followed by its name (`-xo pipefail`).
