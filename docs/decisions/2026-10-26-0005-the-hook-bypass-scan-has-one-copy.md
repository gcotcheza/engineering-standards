# The hook-bypass scan has one copy, here, run against an app root

Card 746 (S1). `scripts/hook-bypass-scan.sh` and its cases, `scripts/hook-bypass-scan-test.sh`, are lifted from Memento at 466b957 (its scan was Fineprint's, widened with the routes this repository's deploy-library suite scan names; Fineprint keeps an older copy). Like `decisions-check.sh`, an app runs it from the central checkout against its own root, through its gate: `HOOK_BYPASS_GIT="$GIT" bash <standards>/scripts/hook-bypass-scan.sh <app-root> [<skipped path>...]`. Exit 0 clean, 1 with one line per finding, 2 when nothing was judged. This repository's gate runs it over its own tree and runs its cases in step 2. Apps move to this copy, and delete theirs, in follow-up cards; until then their own copies are findings when this one scans them.

**What is skipped, and nothing else.** Every file git lists under `docs/`, in every app. The scanner itself, by its resolved path, since it names every route; an app's own copy of it is judged. And each path the caller names after the root, exact (never a directory or a prefix), skipped whole. The skips are arguments, not a file the scanner reads: the smallest form, in the one line of the app's gate that a reviewer already reads, with no file format to validate. This repository skips eight: `CHANGELOG.md`, `ENGINEERING-STANDARDS.md` and `ROLLOUT.md` name the routes in prose; `scripts/gate-run.sh`, `scripts/lib/gate/run.sh`, `scripts/lib/gate/compose.sh` and two mutant tables run a root git under `env -i ... HOME=/root`, root's own home, which the `HOME=` rule cannot tell from another one. A pass for that form would be a third pass, which needs the advisor.

**Two passes, as in Memento.** `-e HOME=` or `--env HOME=` after `docker run` or `docker compose run`, before that command ends; and `git config --get core.hooksPath` with nothing after the key but a command end.

**One deliberate difference from this repository's suite scan, in the short `-n` rule only.** After `commit` or `merge`, quoted or not, the rest of the logical line is judged up to a command separator (`;`, `&` or `|` outside quotes; the `&` of `>&`, `<&` or `&>` and the `|` of `>|` are redirections), and a quoted string is blanked to one word, a flag only when it is a whole flag cluster. So a dash-n inside a `-m` message or after `&&` is not a finding here. Everywhere else the scan matches the suite scan or is wider (comment lines are judged, the hooks key in any case).

**Two rules new in this copy (the advisor's review of 466b957).** An empty quote pair, `''` or `""`, splits a word for nothing: ``git c''ommit -n`` is a commit with the short flag, and `core.hooks''Path` is the hooks key, yet both got past every text rule. Each pair is now dropped from a line before anything is judged, even inside the other quotes, which can only add findings. The cases therefore hide their own routes with a `@` that the fixture writer drops, never with a quote pair. And the read pass now needs `--get` as its own word: `git config --unset --no-get core.hooksPath` unsets the key, and was found only because the read pattern happened to need two dashes before `get`.
