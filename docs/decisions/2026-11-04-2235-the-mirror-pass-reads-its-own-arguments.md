# The mirror pass reads its own arguments

Card 929 (S1), the advisor's ruling, narrowed by review round 1 of ES #82. A deploy script runs root's mirror's git with a home of its own (`env -i … HOME="$MIRROR_HOME" … "$MIRROR_GIT" -C "$MIRROR" …`), and the hook-bypass scan (decision: the-hook-bypass-scan-has-one-copy) reads that `HOME=` and that `env -i` as routes. One pass in `scripts/hook-bypass-scan.sh` lets the read-only forms through, and nothing else; the `decision:` comment beside `MIRROR` points here.

**The shape, as written, on one logical line.** `env -i`, assignments, `HOME=` one variable (`$X`, `${X}`, `"$X"` or `"${X}"`), assignments, a git word, `-C` and one word, at most one `-c gpg.program="$X"` (or `"${X}"`), then `fetch`, `rev-parse`, `log`, `cat-file` or `merge-base` as its own word, then words up to the line end, an optional `)` that closes a substitution, or `; }` that closes a function body. A git word is `git`, a path ending in `/git`, or one variable whose name holds `GIT` or `git`. A word holds no blank, `;`, `&`, `|`, backtick, parenthesis or redirection outside single quotes, and a single-quoted part holds no blank, so `--format='%G?|%GF|%GK'` is one word. In that span the `HOME=` and the `-i` are not findings; anything else in it, and the rest of the line, is judged as before, and the de-quoted copy is taken from the passed line, so it cannot bring the two back.

**Refused outright.** Any backslash in the span. Bash decodes `$'\x2d\x2dupload-pack=…'` (or `--$'\x75'pload-pack`, or `$'\055-upload-pack'`) to an option the scan's own reading never sees, and every `$'…'` that bash reads otherwise than `'…'` holds a backslash; a `$'…'` with none is the plain single-quoted word, so it is not refused on its own. A backslash before a double quote also ends a value where the scan's reading of the assignments does not. And `"$@"`, `${@}` or `$*`, even quoted: a caller could add any option, so the subcommand and its arguments are written out.

**Env names (B2).** Each assignment's name must be `PATH`, `GNUPGHOME`, `GIT_NO_REPLACE_OBJECTS` or `HOME` (the one variable home; a second `HOME=`, or an XDG home, is still a finding). Any other name refuses the pass: fetch runs the value of `GIT_SSH_COMMAND`, `GIT_PROXY_COMMAND` or `GIT_ASKPASS`, `GIT_ALLOW_PROTOCOL=ext` lets an `ext::` remote run a command, a glob (`/usr/bin/g?t`) hides git from any reading of a value, and `LD_PRELOAD` or `GIT_EXEC_PATH` swap the code that runs. This replaces round 1's refusal of a git word in an assignment, which read values and missed the glob. `LANG` and `LC_*` are not on the list: no mirror line sets them.

**One -c (R1).** Only `-c gpg.program="$X"`, which `log --format=%G?` checks signatures with. Unquoted it word-splits into a second `-c`, so `gpg.program=$GPG` refuses the pass, as do `gpg.ssh.program`, `gpg.x509.program`, any other key, a second `-c`, a suffix on the variable, and a `-c` before `-C`.

**Each argument, read as bash reads it once its quotes go.** An argument that does not open with `-` (a remote, refspec, revision or object) passes; an option passes only on its subcommand's list, compared exactly:
- `fetch`: `--quiet`, `--no-tags`, `--prune`. So no `--upload-pack` or any prefix of it, quoted or not, and no `--depth`, `-q` or `--QUIET`.
- `rev-parse`: `--verify`, `--quiet`.
- `log` (R2): `-<n>`, `-n` with a number next, `--format=…`, `--pretty=…`. No `--ext-diff`, `--textconv`, `-p`, `--patch`, `-u`, or `--output=`, which writes a file and could overwrite a `.gitconfig`.
- `cat-file` (R3): exactly two words, `commit`, `tree`, `blob`, `tag`, `-t`, `-s`, `-e` or `-p`, then one that does not open with `-`. No `--textconv`, `--filters`, `--path` or `--batch…`.
- `merge-base` (R4): `--is-ancestor`.

Each subcommand is a builtin, which no alias can hide, and none makes a commit. `verify` is not a git command (git would run the isolated home's `alias.verify`), so it stays off the list, and `rev-parse --verify` is the read.

**Known limits.** The scan reads text, not values. A variable argument (`"$MIRROR_URL"`, `"$1"`) whose value opens with `-` is an option to git, and passes. So does a `$GPG`, a `$PATH` or a `$MIRROR_HOME` whose config names a command (`remote.<name>.uploadpack`, `protocol.ext.allow`), and a value that runs a script which runs git, the `bash -c` gap of the scan's own decision. A prefix kept in a variable with no subcommand (`local GIT="env -i … HOME=$H $MIRROR_GIT -C $M"`) and a function handed on as a runner (`ci_evidence … mirror_run`) stay findings or unseen (card 931). Everything off this shape stays a finding: a subcommand off the list, quoted or longer, no `-C`, any other option before the subcommand, a literal home, a suffix or default on its variable, `env` without `-i`, and a word not named for git. A line the pass cannot clear is rewritten as one function per call, whose body names the subcommand and spells out its arguments: `mirror_main_sha() { env -i … HOME="$MIRROR_HOME" … "$MIRROR_GIT" -C "$MIRROR" -c gpg.program="$GPG" rev-parse --verify --quiet 'refs/heads/main^{commit}'; }`.
