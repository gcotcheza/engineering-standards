# T9's check follows the shared deploy lib

Apps no longer vendor the deploy lib: their gates source `${DEPLOY_LIB}/ledger.sh`, with `DEPLOY_LIB` pinned to `/srv/engineering-standards/scripts/lib/deploy` by the app's own `scripts/lib/gate/deploy-lib.sh`. `gate-image-tags.sh` followed only sources inside the app tree, so every bare `docker compose` call below that source line came out unjudged and the check went red. Reflection's browser gate moved its ledger arm below such a call to get past it, which card 717 (arm before anything runs) forbids.

The check now resolves a source path that starts with `$DEPLOY_LIB/` or `${DEPLOY_LIB}/` against `scripts/lib/deploy` of the standards clone the check itself runs from, and only on positive proof that the gate pinned it there. Proof is two things. First, the chain of files the gate sources, above that line, sources the app's `scripts/lib/gate/deploy-lib.sh`, and that file's first code (comment lines aside, whitespace normalised, nothing else) is exactly the pin block every app carries: `DEPLOY_LIB_CLONE` and `DEPLOY_LIB` set to the standards clone, then the test seam that points `DEPLOY_LIB` at `$DEPLOY_LIB_TEST_CLONE` only inside the guard that requires `DEPLOY_LIB_HARNESS=deploy-lib-test` and a non-root user. Accepting that seam is safe: the guard refuses it for root, who runs every real gate, and the helper's `deploy_lib_ready` refuses to run with it set. Code before the block (a wrapping `if`, a `return`) breaks the match. Second, no file in the chain, the helper's rest included, mentions the name `DEPLOY_LIB` except as a plain read, `$DEPLOY_LIB` or `${DEPLOY_LIB}`. Any other use (an assignment, `export`, `read`, `eval`, a nameref, `unset`, `exec {DEPLOY_LIB}<`, `${DEPLOY_LIB:=}`, a `-e DEPLOY_LIB=` argument) leaves every `$DEPLOY_LIB/` line of that gate script unjudged, wherever it sits in the chain, because a function or a loop makes "below the line" meaningless. The name is matched as a token, so `DEPLOY_LIB_CLONE` or `GATE_DEPLOY_LIB_SUITE` do not count. Comments are not exempt: telling a comment from code needs a shell parser, and an `eval`'d string can turn a `#` line back into code.

Round 2 enumerated assignment forms instead; review found nine it missed (another sourced file, `eval`, `IFS= read`, `if X=`, an export list, a nameref, `while read`, an inherited value), so the enumeration was removed. What this still cannot see is a name built at run time (`eval "DEPLOY_""LIB=x"`, `printf -v "$n"`), and a helper sourced inside a branch that does not run; both need a shell evaluator, not a text check.

A followed file is accepted only when its fully resolved path (`readlink -f`, so a symlink inside the lib counts by its target) lies inside the lib's physical path (`pwd -P`). Only a path that came through `$DEPLOY_LIB/` is held to the lib; a literal path into the lib, or another variable whose rest happens to land there, is judged by the app-tree rule and stays unjudged. A copy of the check with no `lib/deploy` beside it reads no `$DEPLOY_LIB/` path at all.

Cases 65 to 80 in `gate-image-tags-test.sh` hold each part; the mutant sweep is in the PR's commit message.
